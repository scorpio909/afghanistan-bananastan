# Arcanus Prime

**A distributed data processing and analysis system built on Apache Spark and designed for GPU acceleration with NVIDIA.**

This project represents the reforged architecture of the original Arcanus system, transmuting its core concepts into a scalable, distributed, and GPU-ready platform. It is built on the principles of a unified state (Delta Lake), a canonical data model (DataFrame Schema), and a distributed transformation engine (Spark with vectorized UDFs).

## Architectural Principles

1.  **Distributed Sovereignty:** The system is designed to scale horizontally across a cluster of machines.
2.  **Data as the First Citizen:** The architecture is data-centric, with all logic expressed as transformations on distributed DataFrames.
3.  **Immutability and Laziness:** Logic is defined as a series of immutable transformations, optimized and executed by Spark's engine.
4.  **GPU Symbiosis:** The system is architected to leverage NVIDIA GPUs via vectorized Pandas UDFs, including a demonstration of CuPy integration for native GPU computation. This brings massive performance gains where applicable.

## Features

* **Claim Enrichment (GPU-Accelerated):** The ETL job enriches claims using **vectorized Pandas User Defined Functions (UDFs)**, optimized for NVIDIA GPUs where CuPy is available:
    * `compress_symbol_udf`: Compresses symbol value and relation flags into a binary blob using zstandard. Returns `None` on error.
    * `calculate_resonance_udf`: Determines a resonance score based on blob size and relation characteristics. This UDF leverages CuPy for GPU acceleration if available, otherwise falls back to NumPy.
* **Advanced Analytics:** The Analysis job performs system-wide calculations:
    * **System Entropy:** Calculates the Shannon entropy of the system (in bits) based on claim resonance distribution.
    * **Self-Awareness Score (Ratio):** For each claim, a `self_awareness_score` is calculated as the ratio of its resonance to the average resonance for its source. The final summary includes the average `self_awareness_score` per source.
    * **Summary Aggregations:** Provides counts of claims and total resonance per source.

## How to Run

### 1. Setup Environment
First, run the setup script to create a Python virtual environment and install dependencies.
```bash
bash setup.sh
```
The `setup.sh` script will guide you on CuPy installation, ensuring it matches your NVIDIA CUDA version. It also installs other necessary packages like PySpark, Delta Spark, Pandas, etc.

Activate the environment before proceeding:
```bash
source venv/bin/activate
```

**Prerequisites (mentioned in `setup.sh` output):**
*   Apache Spark (e.g., version 3.5.0, matching `pyspark` in `setup.sh`) must be installed and `SPARK_HOME` configured.
*   For GPU acceleration:
    *   NVIDIA CUDA drivers must be installed.
    *   The RAPIDS Accelerator for Apache Spark JAR. Download the version compatible with your Spark and Scala versions (e.g., Spark 3.5.0 usually uses Scala 2.12) from the [NVIDIA RAPIDS Accelerator releases page](https://docs.nvidia.com/spark-rapids/user-guide/latest/getting-started/get-spark-rapids.html#getting-the-rapids-accelerator-for-apache-spark-jar-s). You'll need its path for `spark-submit`.

### 2. Run the Pipeline
The system operates in distinct stages. Run them in the following order.

**Stage A: Ingest Raw Data**
This script generates sample raw data and places it in the default landing zone (`data/landing/claims`).
```bash
python -m arcanus.data_ingestion
```
This uses paths defined in `arcanus/config.py`. Around 1000 records will be generated by default. You can modify `arcanus/data_ingestion.py` to generate more.

**Stage B: Run the ETL Job**
This Spark application reads raw data, enriches it, and saves it to a Delta Lake table.
Replace `/path/to/your/rapids-accelerator.jar` with the actual path to your downloaded RAPIDS Accelerator JAR.

Example using default paths (from `arcanus/config.py`):
```bash
spark-submit \
    --jars /path/to/your/rapids-accelerator.jar \
    --conf spark.plugins=com.nvidia.spark.SQLPlugin \
    --conf spark.rapids.sql.enabled=true \
    --conf spark.python.default.python.exe=./venv/bin/python \
    arcanus/etl_job.py
```
To use custom paths:
```bash
spark-submit \
    --jars /path/to/your/rapids-accelerator.jar \
    --conf spark.plugins=com.nvidia.spark.SQLPlugin \
    --conf spark.rapids.sql.enabled=true \
    --conf spark.python.default.python.exe=./venv/bin/python \
    arcanus/etl_job.py \
    --landing-zone-path /your/custom/landing_data \
    --delta-lake-path /your/custom/delta_lake_output
```
**Notes:**
*   The `\` for line continuation in `spark-submit` are for Unix-like shells. Adjust if using a different shell (e.g., PowerShell).
*   The `--conf spark.python.default.python.exe=./venv/bin/python` is crucial for Spark executors to use the Python environment with all dependencies (like CuPy, zstandard). Use an absolute path if `./venv/bin/python` is not found from the execution directory of spark-submit.
*   Additional RAPIDS configurations are present in `arcanus/spark_session.py` but can be overridden via `--conf` flags here if needed (e.g., GPU memory, task allocation).

**Stage C: Run the Analysis Job**
This Spark application reads from the Delta Lake table, performs analytics, and writes a summary.
Replace `/path/to/your/rapids-accelerator.jar` accordingly.

Example using default paths:
```bash
spark-submit \
    --jars /path/to/your/rapids-accelerator.jar \
    --conf spark.plugins=com.nvidia.spark.SQLPlugin \
    --conf spark.rapids.sql.enabled=true \
    --conf spark.python.default.python.exe=./venv/bin/python \
    arcanus/analysis_job.py
```
To use custom paths:
```bash
spark-submit \
    --jars /path/to/your/rapids-accelerator.jar \
    --conf spark.plugins=com.nvidia.spark.SQLPlugin \
    --conf spark.rapids.sql.enabled=true \
    --conf spark.python.default.python.exe=./venv/bin/python \
    arcanus/analysis_job.py \
    --delta-lake-path /your/custom/delta_lake_input \
    --analysis-output-path /your/custom/analysis_summary_output
```

### Inspecting Output
*   Raw data (Parquet): `data/landing/claims/` (or your custom input path for ETL)
*   Enriched data (Delta Lake format): `data/delta_lake/arcanus_claims/` (or your custom output path from ETL / input for Analysis)
*   Analysis summary (Parquet): `data/delta_lake/analysis_summary/` (or your custom output path from Analysis)

You can inspect Parquet files or Delta tables using Spark, Pandas, or other tools. For example, to quickly view the analysis summary with Spark:
```python
# In a PySpark shell or another script (ensure venv is activated)
from pyspark.sql import SparkSession

# If pyspark is not on PATH, you might need to set SPARK_HOME
# import os
# os.environ['PYSPARK_PYTHON'] = './venv/bin/python' # Or absolute path

spark = SparkSession.builder.appName("InspectSummary").getOrCreate()
summary_df = spark.read.parquet("data/delta_lake/analysis_summary") # Use your actual output path
summary_df.show(truncate=False)
spark.stop()
```
